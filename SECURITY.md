# Security and permissions

This is a preview of a remote connection to your own desktop Codex. It has security controls, but has **not** received an independent security audit. Open source, checksums and passing CI are not a security certification.

## What installation runs

The Skill contains instructions and executable Node.js helpers. Installation copies the gateway into the current user's local data directory, installs locked `qrcode` / `ws` dependencies with npm lifecycle scripts disabled, and verifies the selected tunnel binary against a pinned SHA256. The Windows tunnel is included; the Mac tunnel comes from a fixed HTTPS URL.

These helpers run with the current OS user's permissions. They are not a sandboxed browser extension. Review the repository and publisher before running them. Checksums detect differences from the published file; they do not protect against a publisher account or repository compromise that replaces both code and hashes. The current Windows tunnel does not have an Authenticode publisher signature.

Installation adds no login item or scheduled startup task. It does not change desktop Codex's approval policy, model or project permissions, and does not require you to paste account passwords or API keys into the Skill.

## What scanning authorizes

Treat the pairing QR as an authorization credential. It expires after two minutes and is single-use. Scan only a QR generated by your own trusted computer.

**Default pairing grants computer-level Codex read and dispatch access.** An authorized phone can read the computer's permitted Codex chat list/history and send requests to its fixed desktop entry. The fixed entry is a routing choice, not a security sandbox limited to that one chat: desktop Codex may work across projects or chats using its existing capabilities. If desktop Codex has broad filesystem/network permissions, requests arriving from the phone inherit that boundary.

The connector offers read-only pairing to operators, but the normal flow grants both read and dispatch. It must not be described as a permission-free plugin or as access only to the currently visible conversation.

## Transport and credential storage

- The gateway HTTP listener binds to loopback; the external connection uses HTTPS through the relay/tunnel. TLS verification is not bypassed by the installer.
- The gateway stores hashes of device access tokens and short-lived pairing codes. Session bearer tokens expire after 15 minutes. Device authorization can be revoked.
- Android pairing credentials are encrypted using Android Keystore and AES-GCM. Computer-side state/request records are protected by local file permissions; this is not a claim that all stored data is encrypted.
- Mac local administration uses a private Unix socket. Windows uses a per-installation named pipe, current-user directory ACLs and an additional private administration capability.
- Relay services and AI providers are separate trust/dependency boundaries. We do not claim that third parties receive no metadata or that the entire MoeCast system has independently verified end-to-end encryption. Upstream descriptions are not a MoeCast audit: see [HAPI installation / relay](https://hapi.run/docs/guide/installation) and [HAPI privacy](https://hapi.run/docs/privacy). This connector does not install the full HAPI Hub or Runner.

## Stopping and removing access

Use the Skill's `devices` / `revoke` commands to inspect or revoke a phone authorization, and `stop` to stop the owned connection services. Revocation blocks subsequent access; it cannot undo work already accepted by desktop Codex.

`uninstall` stops owned connection services and removes the connector program while retaining saved identity/history. Revoke a lost or untrusted phone explicitly rather than assuming that uninstalling a client or closing a window revokes the device.

## Verification status — 2026-11-03

The isolated protocol tests cover pairing expiry/reuse, authentication, revocation, permission/path checks and local administration capabilities. Windows CI exercises installation, ACLs, process ownership and named pipes, without a signed-in user's desktop or real phone. Windows desktop/phone acceptance is still in progress.

An audit of the connector's production npm dependency tree against the official npm advisory endpoint on this date reported zero known vulnerabilities. This does not cover unknown issues, all Go dependencies, desktop Codex, operating-system flaws, relay operations or a penetration test.

Do not publish pairing codes, tokens, credential files or private logs in an issue. Report the affected connector version and sanitized failing stage. A private vulnerability-reporting channel and an independent audit have not yet been established; do not publish an exploitable credential or detailed exploit in a public issue.
